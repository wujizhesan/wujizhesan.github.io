Agent 学习指南：从提示词到自主工作流

2026-08-13
2026-08-13
2k
8m
人工智能
AIAgentLLM学习笔记

大语言模型擅长理解和生成内容，但真正的 Agent 会把“想法”变成“行动”：读取信息、拆分任务、调用工具、观察结果，再决定下一步。

学习 Agent 的关键，不是记住更多框架，而是理解一个能够持续运行、可以验证结果的决策循环。

什么是 Agent ​

可以把 Agent 看成由五个部分组成的系统：

模块作用
模型理解目标、推理并生成下一步行动
指令约束角色、目标、边界和输出格式
工具连接文件、终端、浏览器、数据库与外部服务
记忆保存任务状态、历史信息和长期知识
反馈检查工具结果，判断继续、重试还是结束

普通聊天通常在一次回答后结束，而 Agent 会运行一个循环：

text
接收目标
  → 分析当前状态
  → 选择下一步行动
  → 调用工具
  → 观察执行结果
  → 校验是否完成
  → 继续或结束

这个循环常被称为 Agent Loop，也是理解各种 Agent 框架的共同入口。

先掌握四个基础概念 ​

1. 提示词不是全部 ​

提示词负责告诉模型“要做什么”，但稳定的 Agent 还需要明确：

  • 成功条件是什么
  • 哪些工具可以使用
  • 哪些操作需要确认
  • 出错时如何重试
  • 什么情况下必须停止

好的系统指令更像一份运行规则，而不是一句万能咒语。

2. 工具调用让模型接触真实世界 ​

模型本身不能直接读取你的文件、执行命令或访问数据库。工具调用为模型提供结构化能力，例如：

json
{
  "name": "search_notes",
  "arguments": {
    "keyword": "Agent"
  }
}

应用程序执行工具后，把结果返回给模型。模型再根据结果继续推理，而不是假装操作已经完成。

3. 记忆需要分层 ​

常见的记忆可以分为三类：

  • 工作记忆：当前对话和正在处理的任务状态
  • 情景记忆：过去执行过的任务、错误和结果
  • 语义记忆：文档、知识库、代码索引等长期知识

记忆不是越多越好。信息过量会增加成本，也会干扰判断。实践中应优先保存结论、来源和可恢复的任务状态。

4. 结果必须可验证 ​

“模型说完成了”不等于任务真的完成了。可靠的 Agent 会用测试、构建、文件差异、接口响应或页面截图验证结果。

例如，修改代码后的完成条件可以写成：

text
代码已修改
且类型检查通过
且相关测试通过
且没有改动任务范围之外的文件

从单 Agent 开始 ​

初学时，不要急着组建复杂的多 Agent 团队。先完成一个最小闭环：

  1. 接收一个明确目标。
  2. 让模型选择一个工具。
  3. 执行工具并返回真实结果。
  4. 让模型判断是否达到完成条件。
  5. 设置最大循环次数，避免无限运行。

第一个练习可以是“读取一份笔记并生成摘要”。它只需要文件读取和文件写入两个工具，却能完整展示 Agent Loop。

规划与执行 ​

任务变复杂后，可以把 Agent 分成两个阶段：

  • 规划：识别依赖、风险和验证方式，形成可执行步骤
  • 执行：逐步调用工具，并根据结果动态调整计划

计划不应是一成不变的清单。工具返回的新信息可能证明原计划错误，这时 Agent 应更新计划，而不是机械地继续。

一个实用的任务状态通常只有三种：

text
pending → in_progress → completed

同一时间只保留一个进行中的步骤，可以明显降低状态混乱。

什么时候使用多 Agent ​

当任务可以被清晰拆成互不依赖的部分时，多 Agent 才真正有价值。例如：

  • 一个 Agent 调研资料
  • 一个 Agent 编写实现
  • 一个 Agent 运行测试并审查结果

如果多个 Agent 同时修改同一个文件，协调成本可能高于并行收益。因此，多 Agent 的重点不是数量，而是清晰的职责、隔离的工作区和统一的验收标准。

权限与安全边界 ​

Agent 能调用工具，也意味着它可能执行高风险操作。至少应建立这些边界：

  • 默认限制文件写入范围
  • 网络访问使用域名或接口白名单
  • 删除、发布、支付等操作需要额外确认
  • 密钥只通过环境变量或密钥管理服务提供
  • 工具参数在执行前进行类型和路径校验
  • 为循环次数、运行时间和调用成本设置上限

权限设计应该遵循最小权限原则：只开放完成当前任务真正需要的能力。

一条可执行的学习路线 ​

第一阶段：理解模型与工具 ​

  • 掌握消息角色、上下文窗口和结构化输出
  • 实现一个带参数校验的工具调用
  • 记录每一步输入、输出和错误

第二阶段：实现 Agent Loop ​

  • 支持模型选择工具并读取执行结果
  • 添加最大步数、超时和失败重试
  • 用明确的完成条件结束循环

第三阶段：加入记忆与检索 ​

  • 保存任务摘要和关键事实
  • 为本地文档建立检索能力
  • 比较“完整历史”和“压缩摘要”的效果

第四阶段：处理真实任务 ​

  • 选择一个可自动验证的场景
  • 增加计划、状态管理和人工审批
  • 使用测试或数据指标评估成功率

第五阶段：探索多 Agent ​

  • 按职责拆分研究、实现和验证
  • 隔离文件修改范围
  • 由主 Agent 汇总结果并完成最终验收

推荐的第一个项目 ​

可以实现一个“代码仓库学习助手”：

  1. 扫描项目目录结构。
  2. 找到入口文件和主要模块。
  3. 搜索用户提出的关键词。
  4. 引用真实文件路径回答问题。
  5. 输出一份简短的学习路线。

这个项目不依赖复杂界面，却能同时练习工具调用、上下文管理、检索、规划和结果验证。

常见误区 ​

  • 把 Agent 等同于一段很长的提示词
  • 工具执行失败后仍然假设结果成功
  • 一开始就创建大量角色，忽略协调成本
  • 保存所有历史信息，导致上下文越来越混乱
  • 没有完成条件，让循环只能依赖模型自行停止
  • 只展示演示效果，不记录成功率、成本和失败原因

总结 ​

Agent 的核心能力可以浓缩成一句话：在明确边界内，持续选择行动，并用真实结果修正下一步。

从一个工具、一个循环和一个可验证目标开始。等单 Agent 能够稳定完成任务后，再逐步加入规划、记忆、多 Agent 协作与更细致的权限控制。这样学得更快，也更容易真正做出可靠的 Agent 应用。
